# TeamFirst MVP Roadmap

**기간**: 8주 (사용자 ↔ Claude Code 페어 프로그래밍 기준)
**시작**: 2026년 6월
**목표 출시**: 2026년 7월 말 베타 오픈

> 1인 + Claude Code 페어 프로그래밍 환경 기준입니다.
> 사용자(정기윤 과장)는 의사결정·QA·도메인 지식 제공, Claude Code는 구현 담당.

---

## 주차별 마일스톤

### 1주차 — 셋업 & 인증 골격
**산출물**
- [ ] Next.js 15 프로젝트 초기화 (TypeScript strict + Tailwind + shadcn/ui)
- [ ] Supabase 프로젝트 생성 (Seoul region)
- [ ] `001_init.sql` + `002_rls.sql` 적용
- [ ] 이메일/카카오 OAuth 로그인 동작
- [ ] 역할별 라우트 가드 (`(client)`, `(partner)`, `(admin)`)
- [ ] Vercel 배포 + 서브도메인 연결 (`app.teamfirst.kr`)
- [ ] Resend 이메일 발송 테스트

**완료 기준**: 운영자 1명·테스트 광고주 1명·테스트 파트너 1명 계정으로 각자 자기 빈 대시보드 접근 가능

---

### 2주차 — 파트너 온보딩
**산출물**
- [ ] `/partner/apply` 공개 폼 (Tally `mRA0ld` 대체)
- [ ] 파일 업로드 (사업자등록증, 포트폴리오) — Supabase Storage
- [ ] 운영자 대시보드: 신청 목록 + 상태 변경
- [ ] 입점 승인 시 글로싸인 링크 첨부 (수동)
- [ ] 계약 완료 시 파트너 계정 자동 발급 (이메일 + 임시 비번)
- [ ] 카테고리 태깅 UI

**완료 기준**: 정 과장님이 테스트 대행사 1개를 등록→검토→계약→계정 발급까지 직접 해봄

---

### 3주차 — 매칭 요청서
**산출물**
- [ ] `/client/request/new` 단계별 폼 (Tally `3yBY1W` 대체)
- [ ] `react-hook-form` + `zod` 스키마 검증
- [ ] 광고주 대시보드: 요청 목록 + 상세
- [ ] 운영자 대시보드: 요청 검수 + 발송 대상 미리보기
- [ ] **n8n webhook 연결**: 새 요청 제출 시 트리거 (기존 RFP 자동 발송 워크플로우 호환)
- [ ] `rfp_notifications` 자동 생성 로직

**완료 기준**: 테스트 광고주가 요청 제출 → 모든 contracted 파트너의 `rfp_notifications` 생성 확인

---

### 4주차 — RFP 열람·지원
**산출물**
- [ ] 파트너 대시보드: RFP 목록 (도착 알림, 읽음 표시)
- [ ] `/partner/rfp/[id]` 상세
- [ ] `/partner/rfp/[id]/apply` 지원서 폼 (Tally `lbBZNB` 대체)
- [ ] 운영자 대시보드: 지원자 목록 + 비교 뷰
- [ ] 지원 제출 시 광고주에게 이메일 알림 (집계 — 매일 1회)

**완료 기준**: 테스트 파트너 3개가 한 RFP에 지원 → 운영자가 비교 화면에서 확인

---

### 5주차 — 후보 선정·제안
**산출물**
- [ ] 운영자: 상위 3개사 선정 UI (드래그/체크박스)
- [ ] 추천 사유 입력 + 광고주에게 발송
- [ ] 광고주: 후보 카드 뷰 (포트폴리오, 제안, 견적)
- [ ] 광고주: 관심/거절 표시 (`candidates.status`)
- [ ] 분석권한 요청 폼 + 광고주 동의 워크플로우
- [ ] `ad_spend_history` 업로드 UI (지난 3개월 광고비)

**완료 기준**: 운영자가 후보 3개 선정 → 광고주가 받아서 관심 표시 + 광고비 업로드 완료

---

### 6주차 — 미팅 일정
**산출물**
- [ ] 광고주: 일정 후보 3개 선택 (시간대 피커)
- [ ] 파트너: 일정 후보 응답 (수락/대안 제시)
- [ ] 일정 확정 시 양쪽 + 운영자에게 캘린더 첨부 이메일 (.ics)
- [ ] 운영자: 미팅 캘린더 뷰
- [ ] **미팅 2일 전 자동 리마인드** (구글미트 URL 수동 입력 후 발송)
- [ ] 미팅 후 7일 데드라인 카운터

**완료 기준**: 광고주 후보 일정 → 파트너 응답 → 미팅 확정 → 2일 전 리마인드 메일 도착

---

### 7주차 — 이력·알림·UX 다듬기
**산출물**
- [ ] 매칭 요청 **타임라인 뷰** (메일 대체 — 이게 핵심)
  - 제출 → RFP 발송 → 지원 N건 → 후보 3개 → 미팅 잡힘 → 결정 등
- [ ] 인앱 알림 (Supabase Realtime)
- [ ] 광고주·파트너·운영자 대시보드 통계 카드
- [ ] 모바일 반응형 점검
- [ ] 빈 상태(empty state) 일러스트
- [ ] 에러 핸들링·로딩 상태

**완료 기준**: 메일함 안 보고 한 요청의 전 이력을 한 화면에서 추적 가능

---

### 8주차 — 베타 준비 & 데이터 이전
**산출물**
- [ ] **기존 Tally 응답·아임웹 대행사 데이터 마이그레이션 스크립트**
- [ ] 운영자 매뉴얼 (PDF 1장 + 화면 녹화 1개)
- [ ] 파트너 안내 문구 (이메일 템플릿)
- [ ] 광고주 안내 문구 (랜딩에 신규 시스템 안내)
- [ ] Sentry 연결, 로그 확인
- [ ] Privacy Policy / 이용약관 검토
- [ ] **베타 오픈**: 기존 입점사 5곳 대상 1차 테스트

**완료 기준**: 실제 매칭 1건이 신규 시스템 안에서 끝까지 진행됨

---

## Phase 2 (베타 이후 1–3개월)

우선순위 순으로:

1. **매월 광고비 소진액 추적 + 정산 자동화** (가장 큰 페인포인트 후보)
2. 카테고리 기반 RFP 필터링 (입점사 30개 돌파 시)
3. 글로싸인 API 자동 발송
4. 구글 미트 API 자동 생성
5. 매체 이관 자동 안내 템플릿
6. 마케터(프리랜서) 양면 플랫폼
7. 채팅/메시징
8. 광고주 매체사 계정 자동 동기화 (Meta Marketing API, Google Ads API 등)

## 위험관리

| 위험 | 발생 시점 | 대응 |
|---|---|---|
| 1주차 셋업이 늦어짐 | 1주차 | Supabase 무료 plan 한계 점검, 2주차로 일부 이월 |
| 카카오 SSO 심사 지연 | 1-2주차 | 이메일 로그인만으로 베타 진행, 추후 추가 |
| Tally 폼 → 신규 폼 매핑이 누락 | 3-4주차 | `docs/FORM_MAPPING.md` 먼저 완성 후 작업 시작 |
| 운영자가 새 어드민에 적응 어려움 | 7-8주차 | 7주차에 영상 매뉴얼 + 1주 병행 운영 |
| 베타 입점사가 시스템에 대해 거부감 | 8주차 이후 | 기존 메일 알림도 한동안 병행 유지 |
